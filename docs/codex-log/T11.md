# T11 Live OpenAI interpreter with fallback

21 Nov 2026, 11:54–12:00 ICT · Local Windows worktree · Codex, GPT-6

Connected a server-only OpenAI Responses adapter to the scenario interpreter. Both model attempts go through the existing validator and have a nine-second deadline. Each provider call logs model, latency, outcome, validation issue IDs and message length. The SDK's own logging is disabled.

## API and SDK verification

The OpenAI developer documentation MCP tools `search_openai_docs`, `fetch_openai_doc` and `get_openapi_spec` confirmed the model IDs, Responses endpoint and structured-output request. The models support low reasoning effort. GPT-6.2 Sol rejects `none`. [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) · [GPT-6.2 Sol](https://developers.openai.com/api/docs/models/gpt-6.2-sol) · [Reasoning effort](https://developers.openai.com/api/docs/guides/reasoning#reasoning-effort)

The JavaScript SDK calls `client.responses.parse` with `text.format: zodTextFormat(schema, "incident")` and `reasoning: { effort: "low" }`. The server sends `store: false`. The 2,048-token ceiling covers visible output and reasoning together. The installed OpenAI SDK 7.62.0 accepts Zod `^3.25 || ^4.0`, including the project's 4.6.7. The model IDs and dependency versions needed no changes. The SDK defaults to two automatic retries, so the adapter explicitly sets zero retries and a 9,000 ms timeout. [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) · [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) · [openai-node README](https://github.com/openai/openai-node#retries)
