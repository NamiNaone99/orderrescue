# T10b remaining desk states

21 Nov 2026, 12:30–12:52 ICT · Codex local on Windows · gpt-6.2-astra · Node 22 · pnpm 9.15.9

The task was to finish the secondary desk states and preserve the hero dispatch flow. The manual form uses the current scenario catalogue and date. It sends a normal plan request and keeps the same incident for budget updates, stale replanning and confirmation. Both server-calculated strategies and the confirmed reservation rows follow the existing API contracts.

## State walkthrough

| State | How to reach it and what to observe |
| --- | --- |
| Manual entry from the message | Open **กรอกเหตุการณ์เอง**. Choose warehouse A, SKU-X, 13:00–18:00 and submit. The manual result receives focus and the server returns first-come 1/2 at ฿32 and joint 2/2 at ฿88. |
| Clarification and manual entry | Choose **ข้อมูลไม่ครบ** and analyse. The question receives focus. Select **กรอกเอง**, enter an unknown SKU and an end before the start, then submit. Correct the inline errors and submit again. The plan appears after one interpret request for the original message. The manual incident can be replanned after a budget change or B's delay. |
| Analysis, plan, stale and booking announcements | Analyse the afternoon hero sample. The incident receives focus and the polite status region identifies the warehouse, SKUs, window and joint outcome. Apply B's delay to focus Replan. After replanning and confirming, focus moves to the receipt and the status announces the booking. |
| Ignore | Analyse **ถามเรื่องกะงาน**. The result explains that the message is unrelated to picking and the desk sends no plan request. |
| No affected orders | Enter B, SKU-X, 13:00–18:00 in the hero scenario. The empty plan has a nearby Reset button. Press it to return to the initial desk. Already-booked hero orders produce the same empty plan. |
| Best found | Choose real-day, set the budget to ฿100, then manually enter A, SKU 23084, 12:30–13:00. The real solver stops at 200,000 nodes. Focus or tap **ดีที่สุดที่พบ** for the limit. |
| Replayed receipt | In the local uncertain-confirmation browser test, the server books the rows and the first response is dropped. Retry the confirmation with its original key. The receipt and live region show **ส่งซ้ำ ไม่จองเพิ่ม**. |
| Interpreter fallback | Analyse a sample in offline mode. The result names the offline reader. If a second model answers after the primary fails, the line names that model. An offline response with the rate-limit flag also explains the quota. |
| Storage fallback | A health response with degraded memory storage displays a red-outline DB badge and a desk banner. Reading and planning work. A health refresh also disables the final action in an already-open confirmation dialog. Returning to the tab refreshes health and permits confirmation when storage recovers. |
| HTTP 429 | A rejected plan, reservation, reset or interpreter request displays **มีการใช้งานมากเกินไป ลองใหม่ในอีกสักครู่**. Manual entry stays available. A failed reset keeps its receipt until another incident is submitted. |
| Mobile orders | Analyse a case at 390 px or 767 px. Each affected order becomes a card with labeled fields. At 768 px, the desktop table row returns. The 390 px page had no horizontal overflow. |

The Chromium tests run the quota, secondary-model, degraded-health and HTTP 429 states with local response overrides. To step through them use `pnpm e2e e2e/desk-states.spec.ts --debug`. Receipt replay uses a real local reservation and retries its identical request after a deliberately lost response. The solver-limit case uses the committed real-day data and the actual route.

Two early browser runs exposed ambiguous test locators on the rate-limit alert and budget input. The final selectors identify the desk alert and budget spinbutton explicitly.

The receipt is now a tab stop, and the regression check waits for dialog unmount and two animation frames before examining focus.
