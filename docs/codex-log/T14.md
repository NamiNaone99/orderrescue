## Findings and bounds

No counterexample was found and the production solver required no changes. Each oracle input used 2–3 warehouses, each of the two oracle tests had a 60-second timeout and every instance reported `proven`. The oracle's eligible order and stock logic, exhaustive assignment enumeration, and complete ranking use only domain types. The published hero and its ฿87 boundary also anchor that reference implementation.

Nine of the 200 scale inputs at the normal seed reached the node cap. Their affected order counts were 32, 35 (four cases), 37, 38, 39 and 40. Each returned `best_found`. The other 191 were proven, including every generated instance through 31 orders. In the diagnostic run the slowest observed solve was 804 ms. The measured fixtures were independently timed outside the solver for five warm calls on this laptop.

The specified four-location stress input uses D only in test fixtures. Public APIs continue to expose A, B and C. These local results cover generated inputs, both documented hero allocations and a real-day fixture with simulated operational data. Hosted services and the live interpreter were outside T14.
