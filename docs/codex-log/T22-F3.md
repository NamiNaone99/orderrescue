# T22 finding F3. Ground missing incident fields before planning

21 Nov 2026, 13:21 ICT · Codex local on Windows · gpt-6.2-astra

Reproduced the review finding with the submitted message `SKU-X` and a stubbed, schema-valid answer that claimed warehouse A and 13:00–18:00. Before the fix the chain returned an incident. It now asks which warehouse was affected, returns `incident: null`, and finishes after the first interpreter.

## Changes

The validator checks the whole submitted message for a warehouse ID, scenario place name or spoken warehouse label. A named shift must match the scenario's hours. Written endpoints, including dotted clocks and Thai digits, must appear in the text. Spoken times need two explicit endpoints or a spoken endpoint paired with a matching written time. The model interprets spoken names and times. A single endpoint or a vague period prompts for the missing time.

Grounding follows the existing V5 substring check because a fabricated quote must trigger interpreter fallback. A genuine incident can quote only the interrupted activity and name its warehouse elsewhere in the message. Raw output and public response schemas retain their original fields.
