## Transaction, privacy and historical test audit

- The booking route recomputes the six-field confirmation hash and checks the budget. Memory preflights the submitted rows, matches open order lines and quantity, validates grouped revision/available stock/cost, then publishes one replacement snapshot. There is no await between validation and publication. SQL uses one RPC, a key lock, a shared scenario lock, sorted order locks followed by sorted stock-row locks, summed quantities, current costs and transaction rollback. The code never substitutes an allocation or dispatches a failed database reservation to memory. See `lib/api/planning.ts:27`, `lib/store/memory.ts:43–131`, `lib/store/index.ts:13–42` and `supabase/migrations/20261121044705_init.sql:125–215`.
- `lib/planner/affected.ts:17`, `candidates.ts:28`, `joint.ts:20`, `objective.ts:58` and `hash.ts` use canonical order, the fixed scenario clock, inclusive start/exclusive end, net stock, whole lines, five comparison levels and a node cap. Count and deadlines precede cost, then arrivals and assignment IDs. The baseline seeds the joint incumbent. Time and randomness occur outside the search. The missing T14 evidence limits general correctness/scale claims.
- All seven route handlers use strict query/body schemas. Recognized order/SKU, real-calendar timestamp, stock and budget checks occur at their respective boundaries. The 60-order threshold is checked before search. Public state explicitly selects output fields and omits customer and private receipt fields. The app has two server-side log calls, no client `NEXT_PUBLIC_` secret import and no use of `dangerouslySetInnerHTML`. Service-role privileges and RLS in the migration agree with T15's prior hosted inspection. The public UI sources counts, category labels and fields from the derived data, with separate labels for operational simulations and synthetic Thai messages.
- Test history from root shows added checks and helper extraction. The prefilled hero assertion moved to `e2e/helpers.ts:32`; the provenance heading assertion follows the updated heading, and the clarification test gained manual-entry assertions. The offline route case pins the no-key condition. The only conditional exclusions found are the explicitly opt-in hosted contracts, a missing derived seed and a missing build. The seed and browser-bundle checks ran in this review. No deleted correctness assertion, assert-nothing test or unconditional skip was identified.
