# T22 F2. Bound incoming requests and shared planning work

21 Nov 2026, Bangkok. Codex local on Windows, GPT-6. The T22 review requested the two outstanding input guards from SPEC §9 and DEPLOY_PLAN §6. Work used the local memory store and offline interpreter.

## Before and after

On `5b6b055`, seven of nine new contract cases failed. All five POST routes accepted bodies of 16,385 bytes; the local booking returned 201. A stream that understated its length was read to completion. The twenty-first combined planning/reservation request returned 200.

`readBody` now counts incoming bytes, stops on the first chunk past 16,384, and cancels the remaining stream. It decodes UTF-8 across chunk boundaries and parses JSON after the size check. Size violations use the shared `INVALID_INPUT` envelope with HTTP 413. A malformed body within the limit still receives 422. The server uses the actual stream even when the supplied length is missing, too large or too small.

The two planning routes take one token from the same process-local bucket before reading the body or starting domain work. The existing trusted-IP resolver supplies its key. Twenty calls are admitted immediately and one token returns per second. Under exhaustion the routes return 429 `RATE_LIMITED`. Functional route tests get a fresh bucket per case; the guard contract keeps both routes on one uninterrupted bucket and controls the clock.
