## Hero HTTP check

Started a loopback server using `pnpm exec cross-env STORAGE_MODE=memory INTERPRETER_MODE=offline pnpm dev --hostname 127.0.0.1 --port 3136`. On a fresh local hero, ran the following in PowerShell.

```powershell
$body = '{"scenario":"hero","incident":{"warehouse_id":"A","sku_id":"SKU-X","window_start":"2026-11-21T13:00:00+07:00","window_end":"2026-11-21T18:00:00+07:00"},"budget_thb":100}'
$p = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:3136/api/plan' -ContentType 'application/json' -Body $body
foreach ($name in 'first_come','joint') {
    $a = $p.$name
    $pairs = $a.lines | ForEach-Object { '#{0} via {1}' -f $_.order_id,$_.warehouse_id }
    '{0}: {1}/{2}, THB {3}, {4}' -f $name,$a.on_time,$a.total,$a.extra_cost_thb,($pairs -join ', ')
}
```

```text
first_come: 1/2, THB 32, #102 via B
joint: 2/2, THB 88, #101 via B, #102 via C
```

A Node HTTP client using `fetch` confirmed the six-field joint lines. The first response returned 201, replay returned 200 with the same receipt, and the following state read contained exactly one receipt. After resetting the local hero and applying its B slip event, confirming the original rows returned 409 `STALE_STOCK`. A Playwright request client also checked health, state and offline interpretation of the first hero sample. The initial probe looked for `kind`; the corrected probe asserted the public response field `outcome` and all three calls passed.

## Review and verification scope

- The server writes one structured entry per handled request. Tests verify that interpretation adds only the input length and that a successful booking adds the receipt ID. HTTP errors expose safe messages with the request ID.
- The confirmation hash checks consistency of the submitted incident, budget and rows. It provides no server attestation under the public hash contract in SPEC sections 5 and 8. The store independently enforces idempotency, open order lines, revisions, free stock, quantities and costs.
- Quotas live in the server instance. Interpreter retries consume the daily allowance for actual model calls. Local requests share a bucket because their Web Request has no trusted client address. Multiple production instances can each admit their own quota. This task verified the limiter using injected clients and clocks.
- The configured-but-unavailable Supabase mode passed concrete regression checks for degraded health, memory reads, and refused writes with HTTP 503. Live providers and hosted storage were outside this local verification.
