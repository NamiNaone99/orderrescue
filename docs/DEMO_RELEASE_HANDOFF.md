# OrderRescue | ส่งต่อเดโมให้ทีม

21 พฤศจิกายน 2569 · [PR #31](https://github.com/NamiNaone99/orderrescue/pull/31) · [เดโมทีม](https://orderrescue.vercel.app)

## เข้าใจงานในหนึ่งประโยค

เมื่อคลังเตรียมของไม่ทันรอบส่ง คนคุมรอบใช้ OrderRescue เพื่อดูว่าออเดอร์ไหนเสี่ยง คลังไหนส่งแทนได้ และต้องจ่ายเพิ่มเท่าไร ก่อนตัดสินใจจองของตามแผน

## เส้นทางเดโมหลัก

| ทำอะไร | สิ่งที่เห็นบนจอ |
| --- | --- |
| เปิดหน้าเดโมแล้วกด **เช็กออเดอร์เสี่ยง** | ตัวอย่างเริ่มด้วย “คลัง A เตรียม SKU-X ให้ทันรอบบ่ายวันนี้ไม่ได้ครับ” แอปแสดงคลัง A, SKU-X และช่วง 13:00–18:00 พร้อมไฮไลต์ข้อความต้นทาง |
| ลอง **ข้อมูลไม่ครบ** | ระบบถามทีละประเด็น โหมด Live ให้ตอบเพิ่มที่หน้าเดิม โหมด Offline มีคำถามและทางไปกรอกเอง คำตอบในโหมด Live ถูกอ่านพร้อมข้อความเดิม โดยยังอยู่ในขีดจำกัด 500 ตัวอักษร |
| กลับมาดูแผนจากข้อความหลัก | ตามคิวเดิมทัน 1 จาก 2 ใบที่จ่ายเพิ่ม ฿32 จัดคลังใหม่ทัน 2 จาก 2 ใบที่จ่ายเพิ่ม ฿88 สรุปแสดง **เพิ่ม ฿56 เพื่อให้ #101 ทันรอบ** |
| เปิด **ลองคิดว่าจ่ายเพิ่มแล้วคุ้มไหม** | ช่องค่าเสียหายเว้นว่างให้คนกรอกเอง ถ้าคาดว่าการพลาด #101 เสีย ฿100 เดโมคำนวณส่วนต่างสุทธิ ฿44 สมมติว่าเลี่ยงความเสียหายนั้นได้ กรอก ฿30 แล้วจะเห็นว่าจ่ายเพิ่มเกินค่าเสียหาย ฿26 |
| ลองข้อความ **รถสาขา B ออกได้บ่ายสองครึ่ง** ในอัปเดตจากคลัง | เดสก์เสนอเวลา 14:30 พร้อมข้อความที่ใช้ ผู้ใช้กดยืนยันข้อมูลนี้ก่อน แผนเดิมจึงใช้จองไม่ได้และต้องกดเช็กแผนใหม่ |
| กด **ตรวจรายการที่จะจอง** | หลัง B เลื่อน แผนเหลือ #102 จากคลัง B ที่ ฿32 ส่วน #101 ยังต้องจัดการ ให้ตรวจคลัง จำนวน และยอดเพิ่มก่อนกดยืนยันจอง แล้วดูใบจองหรือดาวน์โหลด CSV |

ยอด ฿32 ของคลัง B มาจาก 8 หน่วย × ฿4 ยอด ฿56 ของคลัง C มาจาก 8 หน่วย × ฿7 สต็อก รอบส่ง และต้นทุนในเคสนี้เป็นข้อมูลสมมติ ตัวเลขผลตอบแทนจริงต้องวัดจากค่าใช้จ่ายและการส่งมอบของลูกค้า

## ภาษาและหน้าตา

| ส่วนที่ปรับ | ผลที่คนใช้เห็น |
| --- | --- |
| หัวข้อ | “เตรียมของไม่ทันรอบส่ง?” ตามด้วยสิ่งที่ทำต่อได้ทันที |
| ข้อความตัวอย่าง | ใช้ภาษาคนคลังแจ้งเรื่องเตรียมสินค้า มีตัวอย่างใหม่ให้ทั้ง hero และชุด real-day |
| สถานะและฟอร์ม | “ช่วงที่เตรียมของไม่ได้”, “ของยังไม่พร้อมส่ง” และ “กลับมาเตรียมของได้” ใช้กับการตรวจข้อมูล การกรอกเอง ตารางคลัง และอัปเดตจากคลัง |
| ความคืบหน้า | รับเรื่อง → เช็กข้อมูล → ดูแผน → จองของ พร้อมคำถามและช่องตอบเมื่อข้อมูลยังขาด |
| ลำดับบนหน้า | ผลต่างจำนวนใบและเงินอยู่เหนือการ์ดเปรียบเทียบ งบและปุ่มตรวจรายการอยู่ในคอลัมน์แผน |
| Typography | IBM Plex Sans Thai น้ำหนัก 400, 500, 600 และ 700 ให้เว็บเสิร์ฟไฟล์ฟอนต์จาก build ทั้งบนหน้าหลักและหน้า error |
| UI | เพิ่ม daisyUI 5.8.2 เฉพาะ alert และ badge ของกล่องสรุป โดยใช้ prefix `du-` และสีจากหน้าเดิม ฟอร์มและกล่องยืนยันใช้โครงเดิม |
| ไอคอน | 📦 อยู่เฉพาะหัวช่องข้อความจากคลังและตั้งให้โปรแกรมอ่านหน้าจอข้าม สถานะความพร้อมและการจองมีข้อความกำกับ |

ตัวอย่างใหม่ถูกเติมจากโค้ดแอปในหน้าที่โหลดครั้งแรกและใน State API จึงเห็นคำใหม่ได้แม้ข้อมูลใน Supabase จะสร้างมาก่อน ชุดข้อความเดิมยังใช้เล่นผลทดสอบย้อนหลังได้ และโหมด Offline รู้จักทั้งตัวอย่างเดิมกับตัวอย่างใหม่

## ขอบเขตของ AI

OpenAI อ่านข้อความและเสนอข้อมูลคลัง สินค้า เวลา หรือคำถามกลับ โค้ดตรวจข้อมูลและข้อความอ้างอิงก่อนใช้ ตัววางแผนคำนวณจากออเดอร์ สต็อก เวลาที่ของพร้อม และงบ ผู้ใช้ยืนยันรายงานคลังและการจอง ค่าเสียหายในช่องประเมินใช้เพื่อช่วยตัดสินใจบนหน้าจอเท่านั้น

## เปิดทดสอบและเช็ก release

1. ใช้ Node 22 และ pnpm ตาม lockfile รัน `pnpm install --frozen-lockfile` แล้ว `pnpm dev` ค่าเริ่มต้นใน [.env.example](../.env.example) ใช้ memory และ offline
2. สำหรับ Live ให้ใส่ค่าฝั่งเซิร์ฟเวอร์ใน `.env` หรือ `.env.local` ของเครื่อง ไฟล์เหล่านี้ถูก Git ข้ามไว้ การเชื่อมต่อของ Vercel ใช้ค่าที่ตั้งในโปรเจกต์เดิม
3. ตรวจ `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test` และ `pnpm e2e` เทียบจำนวนใบและค่าใช้จ่ายตามตารางด้านบน ลองมือถือ 390px และใช้คีย์บอร์ดไปถึงหน้าจอง
4. เวอร์ชันส่งงานขึ้นจาก `main` ไปที่ [Vercel URL เดิม](https://orderrescue.vercel.app) ตรวจ SHA ผ่าน [health](https://orderrescue.vercel.app/api/health) ให้ตรงกับ merge commit และดูผล **Deployed smoke** ใน GitHub Actions

หลักฐานก่อนปรับภาษารอบสุดท้ายอยู่ใน [DESK-UX](codex-log/DESK-UX.md) และคำอธิบายห้าเคสอยู่ใน [CASES](codex-log/CASES.md)

### หลักฐานของรุ่นนี้

- Build, lint และ typecheck ผ่าน Vitest ผ่าน 353 กรณี ชุด hosted database 22 กรณีเป็นชุด opt-in ที่ข้ามในรอบบนเครื่อง
- Browser checks ผ่าน 37 กรณีใน 4.7 นาที รวมการถามกลับ การคำนวณเงินส่วนต่าง การจอง กรณีรถเลื่อน คู่มือสาธิตทั้งเส้น และการเปิดทั้งห้าเคส
- ตรวจจาก Chromium ว่าทั้งหัวข้อภาษาไทยและชื่อ OrderRescue ภาษาอังกฤษโหลดไฟล์ IBM Plex Sans Thai จริง ที่ 1280px และ 390px
- เรียก OpenAI จริงด้วยข้อมูลตัวอย่างบนระบบที่อ่าน Supabase ชุดเดิมได้ ข้อความเต็มได้คลัง A, SKU-X และช่วง 13:00–18:00 ข้อความที่เว้นช่วงเวลาได้คำถามถามกลับ
- ตรวจแผนบนชุดจำลอง hero ได้ 1 ใบตามคิว และ 2 ใบที่ ฿88 เมื่อจัดคลังใหม่ ส่วน real-day เคสสินค้า 23084 ได้ 15/21 และ 16/21 ที่ ฿184 ตามเดิม
