## Purpose

Given a warehouse disruption, let a dispatcher compare orders served in arrival order with the best joint allocation found under one shared budget. The synthetic hero should improve from one of two orders at THB 32 to both orders at THB 88.

## Surprises & Discoveries

The planning request carries four incident fields. The richer scenario incident also carries the message and quote. The booking hash covers those four planning fields and six fields per assignment.

The tie fixture gives both greedy seeds the 8-unit order at THB 32. It can demonstrate that the joint search finds the cheaper 4-unit assignment even when the on-time count cannot improve.

The local reviewer supplied twelve equal-deadline orders, one for two units and eleven for one. With 3, 5 and 7 units available at costs 0, 3 and 7, and budget 32, ten single-unit orders fit at THB 29. The earlier bound repeatedly counted the same cheap stock as available to several orders and did not prove this result before its node limit.

## Decision Log

2026-11-21, Codex. Use the request's incident type at the entry point so callers can supply either shape. Compare dates as epoch milliseconds and compare identifiers using ordinal string order. Keep a canonical output order for each list so equal inputs produce byte-identical results.

2026-11-21, Codex. Count each visited search node once. A limit reached exactly at a completed proof is still proven. If a necessary node remains unvisited, return the best known feasible allocation. Equal-cost sources in the joint search branch by warehouse ID to preserve the last objective tie-break.

2026-11-21, Codex. At a fixed search depth, two prefixes with the same stock and budget admit identical remaining assignments. Keeping the better prefix preserves all five objective levels. Enable that cache when the number of possible stock states across depths fits the default node budget, to avoid retaining many one-off states.
