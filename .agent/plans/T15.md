# T15 — Reserve confirmed stock atomically in Supabase

## Purpose

A server using Supabase can reserve the exact confirmed lines with one HTTPS RPC, replay the receipt on retry and reject changed stock. During a storage outage the desk can display the memory scenario and refuse booking.

The first contract run caught a foreign-key error resetting a booked scenario. Removing its reservations first clears the dependent reservation lines before cascading the scenario deletion. All 19 contract cases passed on rerun.

## Decision Log

2026-11-21, Codex. Read the complete snapshot through one security-invoker view. The day has more than 1,000 lines and separately paged HTTP requests could observe different bookings. Aggregation in the database gives each read one consistent transaction snapshot.

2026-11-21, Codex. The five RPC parameters do not include the incident references validated by the memory Store. Pass these references in a single transaction-scoped PostgREST header so SQL can validate them after idempotency and budget. Preserve the six-field confirmed lines and the public function signature.

2026-11-21, Codex. A read fallback marks the affected scenario read-only until its next successful database snapshot. A healthy probe alone cannot make an earlier fallback snapshot safe for booking.
