## Purpose

## Starting point

`lib/domain/contracts.ts` defines the seven request/response shapes and error envelope. The store provides versioned reads, booking, event, reset and health. The planner returns two strategies and `lib/planner/hash.ts` hashes the six confirmable fields. `lib/interpreter` validates messages and records fallback attempts.

## Milestones and steps

1. **HTTP boundary.** In `lib/http.ts`, parse request data, assign a UUID, translate typed failures to the section 9 HTTP statuses and write a log containing only the request identifier and safe status fields. Return a generic message for unexpected failures.
2. **Read and confirm.** Implement health and filtered state, plan against the stored snapshot, compute the joint hash and check the submitted hash and budget before reserving. Return 201 for a new receipt and 200 for replay. Apply only registered demo events through the store.
3. **Limit and reset.** Add configurable per-IP token buckets, a daily interpreter allowance and the hero reset ceiling. Validate interpret length before storage or provider work. When the model quota is empty, return offline with the rate-limit flag. Use constant-time token comparison for privileged resets.
4. **Contract tests.** Call each route with a Web Request. Check each successful schema, section 9 error status and request ID, both notices, limiter refill and daily rollover, exact booking lines and replay, and the hero results.
